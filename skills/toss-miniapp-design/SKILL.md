## 1. TDS (토스 디자인 시스템) 컴포넌트

출처: https://developers-apps-in-toss.toss.im/design/components.md

TDS는 **Toss Design System**의 약자로, 토스 커뮤니티 전반에서 사용하는 디자인 시스템이에요.
디자이너, 개발자, 기획자 등 직군을 구분하지 않고 같은 기준으로 협업할 수 있게 도와줘요.

### TDS 장점

- 사용자에게 일관된 제품 경험을 제공할 수 있어요.
- 디자이너는 UI 구현보다 문제 해결에 집중할 수 있어요.
- 개발자는 커스텀 UI를 만드는 것보다 3~5배 빠르게 개발할 수 있어요.

### 컴포넌트 리스트

앱인토스에서 가장 자주 사용하는 **핵심 TDS 컴포넌트 11개**를 소개해요.
각 컴포넌트를 눌러 사용 방법과 활용 예시를 자세히 확인해 보세요.

## 2. 피그마 (Figma) 디자인 가이드

출처: https://developers-apps-in-toss.toss.im/design/prepare/design.md

TDS 컴포넌트로 디자인하면 개발 문서에 있는 코드를 토대로 빠르게 개발할 수 있어요.

> 라이선스 안내: 본 UI Kit을 사용함으로써, 본 UI Kit에 포함된 [라이선스](https://developers-apps-in-toss.toss.im/design/prepare/figma-ui-license.html)의 조건에 동의하는 것으로 간주됩니다.

### 파일 직접 다운로드 및 설정

다운로드 파일: `TDS_Mobile_for_Apps_in_Toss_(2602-1).zip`

> 유의사항: UI Kit에 적용된 Semantic Color는 현재 버전의 코드와 일치하지 않아요.

1. **파일 다운로드**: 공식 사이트에서 `.fig` 파일을 다운로드해요.
2. **파일 가져오기**: 피그마 상단 메뉴 Import 버튼 → 다운로드한 파일 선택 또는 드래그&드롭.
3. **라이브러리로 연결 (Publish)**: Assets 탭 → 📚 아이콘 → Manage libraries → Publish 버튼.
   - Publish 전: 다운로드 파일 안에서만 사용 가능
   - Publish 후: 다른 피그마 디자인 파일에서도 사용 가능
4. **컴포넌트 사용**: 작업장 Assets 탭 → TDS Library 활성화 → 필요한 컴포넌트를 드래그해서 사용.

> 자동 업데이트는 불가해요. 새 버전이 나오면 다시 파일을 다운로드해야 해요.

### 디자인할 때 꼭 지켜주세요

1. 모든 화면의 최상단에는 **❖ Navigation** 컴포넌트를 반드시 사용해 주세요. 🌈 **Screen**을 꺼내 쓰면 더 편리해요.
2. 가능한 한 **오른쪽 패널에서만 속성을 조작**해 주세요. 캔버스에서 직접 수정하면 코드에 없는 속성이 생길 수 있어요.
3. 화면은 **가로 375px 기준**으로 작업해 주세요. **❖ Keypad** 처럼 반응형 미지원 컴포넌트가 있어요.
4. 화면 상단에는 **❖ Top,** 그 아래에는 **❖ ListRow**를 사용하면 대부분의 화면을 빠르게 구성할 수 있어요.
5. 대부분의 TDS 컴포넌트에는 기본 패딩이 포함돼 있어서 gap 없이 붙여서 사용해도 자연스러워요.

### 자주 묻는 질문 (Figma)

**Q: 컴포넌트가 원하는 대로 동작하지 않아요.**
A: [개발자 커뮤니티](https://techchat-apps-in-toss.toss.im/)로 문의해 주세요.

**Q: 원하는 컴포넌트가 없어요.**
A: 대부분의 UI는 TDS 컴포넌트로 대체할 수 있어요 (예: Card UI 대신 🔵 Mobile_ListRow). 없다면 채널톡으로 요청해 주세요.

**Q: Toss Product Sans 폰트는 설치해야 하나요?**
A: 각 컴포넌트에 이미 적용돼 있어서 별도 설치 없이 사용할 수 있어요.

**Q: TDS 컴포넌트를 분리해서 써도 되나요?**
A: 가능하지만 신중하게 판단해 주세요.

## 3. 앱빌더 (DEUS)

출처: https://developers-apps-in-toss.toss.im/design/prepare/deus.md

앱빌더는 앱인토스 파트너사를 위한 **웹 기반 UI 디자인 툴**이에요.
별도 설치 없이 토스의 UI 스타일 가이드를 따르는 화면을 빠르게 만들 수 있어요.

- 토스 UI 스타일에 맞는 화면을 빠르게 만들 수 있어요.
- 디자인 에셋과 컴포넌트를 바로 사용해 화면을 구성할 수 있어요.
- 프로토타입으로 실제 모바일 화면처럼 미리 볼 수 있어요.
- 콘솔에서 미니앱을 선택하고 디자인 메뉴를 누르면 바로 시작할 수 있어요.
- 현재 베타 버전이에요. 화면 캡처나 녹화본을 외부에 공유하지 말아 주세요.

상세 가이드(프로젝트 생성, 퀵스타트/커스텀 방식, 레이아웃 구성, 미리보기/공유)는 `references/app-builder.md` 참조.

## 4. 미니앱 브랜딩 가이드

출처: https://developers-apps-in-toss.toss.im/design/miniapp-branding-guide.md

앱인토스 서비스가 토스와 명확히 구분되는 브랜드 경험을 전달할 수 있도록 준비한 기준들이에요.
사용자가 토스와 앱인토스를 혼동하지 않도록 하는 데 중요한 기준이니, 꼭 지켜주세요.

### 1. 브랜드 로고 / 이름 / 컬러

#### 브랜드 로고

파트너사의 로고는 전체탭, 혜택탭, 푸시, 알림, 내비게이션, 브릿지에 보여져요.

로고 제작 기준:
- 크기는 600x600px의 각진 정사각형. 모서리가 둥근 형태는 사용 불가.
- 로고 뒤에는 반드시 배경이 있어야 하며, 라이트/다크 모드 모두에서 잘 보이는 배경 색상을 사용해요.
- 로고 자체에 배경이 포함된 경우(예: 애니팡) 이미지를 600x600px 영역에 꽉 차게 배치해요.
- 앱인토스 콘솔에 로고 파일을 업로드하고, `granite.config.ts`의 `appsInToss` 함수에서 `brand.icon` 속성에 동일한 로고 링크를 입력해요.

가이드 파일: `AppsInToss_Logo_Guide_600_600.pdf`, `App_in_Toss_Logo_Guide_600_600.ai`

#### 브랜드 이름

전체 탭, 혜택 탭, 푸시, 알림, 내비게이션, 브릿지에 노출돼요.
특별한 이유가 없다면 한글로 작성해 주세요 (예: `토스` O, `Toss` X).

- 앱인토스 콘솔에 브랜드 이름을 입력해요.
- `granite.config.ts`의 `appsInToss` 함수에서 `brand.displayName` 속성에 동일한 브랜드 이름을 입력해요.

#### 브랜드 컬러

브랜드 컬러는 토스 내 진입점, 브릿지, 버튼 등에 사용돼요.

- 이미 브랜드 컬러가 있다면 그대로 사용해요.
- 없다면 로고에서 가장 많이 사용된 색상을 선택해요. [컬러 추출 사이트](https://lokeshdhakar.com/projects/color-thief/)를 활용할 수 있어요.
- 색 대비 기준 미충족 시 기존 색상을 유지하면서 자동 보정돼요.
- `granite.config.ts`의 `appsInToss` 함수에서 `brand.primaryColor` 속성에 `#` 포함 6자리 헥스 코드 입력 (예: `#3182F6`).

### 2. 내비게이션 바

내비게이션 바는 화면 상단에 고정되는 영역으로, 앱인토스 전용 컴포넌트를 제공해요.

- [게임 가이드](/checklist/app-game.md#_5-내비게이션-바)
- [비게임 가이드](/checklist/app-nongame.md#_4-내비게이션-바)

### 3. 탭바

탭바는 필수 컴포넌트는 아니지만, 사용할 경우 반드시 토스에서 제공하는 **플로팅 형태**의 탭바를 사용해야 해요.
토스 메인 화면의 기본 하단 탭과 형태가 겹치면 사용자가 현재 위치를 헷갈릴 수 있기 때문이에요.

- 탭 개수: 최소 2개, 최대 5개.
- 토스에서 제공하는 플로팅 형태를 유지해야 해요.

## 5. 해상도 가이드

출처: https://developers-apps-in-toss.toss.im/design/resolution.md

미니앱은 여러 해상도/화면 비율의 기기에서 실행돼요. 하나의 논리 해상도를 기준으로 설계하고 에셋을 1x/2x로 준비하면, 실제 트래픽의 대부분을 안정적으로 커버할 수 있어요.

핵심 권장 사항:
- **논리 해상도**: 세로형 약 360x640 ~ 420x740, 가로형 약 640x360 ~ 740x420 중 하나를 기준으로 선택.
- **에셋 해상도**: 1x + 2x 구성이면 충분. 3x는 그래픽 품질이 특히 중요한 경우에만 선택적 추가.
- **풀스크린(게임)**: 콘텐츠가 화면을 완전히 채우고, 레터박스/여백이 없어야 하며, Safe Area를 처리해야 해요.

상세 가이드(데이터 기반 참고, 테스트 기기 가이드, 권장하지 않는 방식)는 `references/resolution-guide.md` 참조.

## 6. 그래픽 리소스

출처: https://developers-apps-in-toss.toss.im/design/resources.md

토스에서 제공하는 그래픽 리소스: 아이콘/이모지(약 7,000개 이상), 스마트폰 목업 파일, 토스트(AI 이미지 생성 툴), 3D 그래픽/애니메이션.

핵심 사용 원칙:

- 핵심 정보를 가리지 않게 배치해 주세요.
- 부정적/호소하는 감정 표현, 장식적 이펙트는 사용하지 마세요.
- 직접 제작 시: 토스 스타일(단순, 명료, 깨끗한 디지털 그래픽)의 일관성을 지키고, 고화질로, 다크/라이트 모드 모두에서 잘 보여야 해요.

## 7. UX 라이팅 가이드

출처: https://developers-apps-in-toss.toss.im/design/ux-writing.md

토스 앱의 보이스톤을 적용한 문구 작성 지침이에요. 핵심 원칙 5가지:

1. **해요체**: 상황/맥락 불문, 모든 문구에 해요체를 적용해요.
2. **능동적 말하기**: 수동형("됐어요") 대신 능동형("했어요"), 과거시제 줄이기, 능동적 동사 사용.
3. **긍정적 말하기**: "안 돼요/없어요" 대신 "~하면 할 수 있어요". 에러 메시지도 긍정형으로 다음 행동을 안내해요.
4. **캐주얼한 경어**: '~시겠어요?', '께' 같은 과도한 경어를 피하고 친근하게 써요.
5. **'{명사}+{명사}' 쓰지 않기**: 한자어를 풀어서 동사 형태로 쓰거나 '{명사}가 {명사}해서' 형태로 풀어써요.

상세 가이드(예시, 예외 규칙)는 `references/ux-writing.md` 참조.

## 8. 소비자 UX 가이드 (다크패턴 방지 정책)

출처: https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md

토스 사용자는 일관되고 신뢰할 수 있는 경험을 기대해요.
아래 사례들은 최소한의 사용 경험 기준을 벗어난 치명적 사용성 오류로, **앱인토스 서비스로 출시할 수 없어요.**

### 1. 서비스에 진입하자마자 바텀시트가 뜨는 경우

전면을 가로막는 광고성 바텀시트(알림 동의 요청 포함)가 노출되면 안 돼요.
사용자는 진입 즉시 의도한 목적을 수행할 수 있기를 기대해요.

### 2. 뒤로 가기 버튼을 눌렀을 때 이전 화면을 막는 바텀시트가 뜨는 경우

이탈을 막기 위한 의도적 인터럽트(알림 동의 유도 등)는 사용자 자율성을 침해하고 신뢰를 떨어뜨려요.

### 3. 나갈 수 있는 선택지가 없는 경우

파트너사가 유도한 CTA 외에 다른 선택이 없는 구조는 강제적으로 느껴지며 반감/불신으로 이어져요.

### 4. 예상하지 못한 순간에 광고가 노출되는 경우

사용 흐름 중 갑작스러운 전면 광고는 몰입을 방해하고 불쾌한 인상을 남겨요.

### 5. CTA 버튼만 보고 다음 행동을 예상할 수 없는 경우

CTA는 사용자가 다음에 무엇을 하게 되는지 명확하게 알려주는 장치예요.
버튼 라벨이 모호하거나 화면 설명만 반복하면 사용자는 클릭 결과를 예측하지 못해 전환율이 저하돼요.
CTA 위에 과장되거나 중복된 보조 설명은 버튼의 역할을 흐리게 해요.
